# blackhole-sim

A physically accurate, real-time renderer of a Kerr (spinning) black hole's accretion disk, running entirely in the browser on WebGPU.

This isn't a stylized visualization — it's a real general-relativistic ray tracer. Every pixel backward-integrates a null geodesic through curved Kerr spacetime, terminating on the event horizon (shadow), the accretion disk (emission), or escaping to the background. Disk brightness and color come from real physics: Novikov–Thorne relativistic disk flux, combined gravitational + Doppler redshift, and blackbody emission mapped through actual CIE color-matching functions into sRGB — not a hand-tuned color ramp.

## Features

- Exact Kerr metric (Boyer–Lindquist), horizons, ergosphere, frame dragging
- Hamiltonian geodesic integration (adaptive RK4) with conserved quantities (E, L_z, Carter constant)
- ISCO, photon orbit, and marginally bound radii for arbitrary spin
- Novikov–Thorne / Page–Thorne relativistic disk flux (correct zero-torque inner boundary — flux peaks just outside the ISCO, not at it)
- Combined gravitational + Doppler redshift (g-factor), producing physically correct approaching/receding disk asymmetry
- Blackbody emission → CIE XYZ → linear sRGB (Wyman et al. color-matching fit) — colour and brightness are the blackbody's visible-band radiance at the observed temperature, not an artist's gradient
- Zoom — 0.25x (the whole disk) to 16x (the photon ring), by the Zoom slider, the mouse wheel or a two-finger pinch (both toward the pointer) or the + / - / 0 keys; share links carry it
- Real-object presets — M87\*, Sagittarius A\*, Cygnus X-1, GRS 1915+105, TON 618, Phoenix A and Interstellar's Gargantua with published mass, spin and viewing angle, physically derived disk temperature, and a caption with sources and caveats
- Physical units — Mass and Accretion (fraction of Eddington) sliders; horizon, ISCO and photon orbit in km/AU, disk peak temperature, ISCO orbital period, playback time scale
- Synchrotron jet — magnetically arrested field, M87's measured acceleration, electrons injected with M87's core spectrum and cooled by their own radiation, exact cyclo-synchrotron emission and self-absorption transferred in general relativity along the geodesics, brightness from energy conservation (the electrons radiate η × the Blandford–Znajek power) in the same units as the disk
- Light-travel delay — each pixel shows its emitter at the time the light left it, so the photon-ring subimages echo the disk tens of M later (toggle in the panel)
- 1.3 mm (EHT) view — a Band switch shows the sky at the Event Horizon Telescope's 230 GHz: below 1 % of Eddington a hot accretion flow (semi-analytic RIAF, density calibrated to the measured flux) replaces the thin disk, in brightness temperature and false colour; Sgr A*'s ring comes out 48 µas against the EHT's 51.8 ± 2.3
- HDR accumulation with ACES tonemapping and progressive anti-aliasing
- Interactive controls: object preset, spin (a*), inclination, mass, accretion, band (visible / 1.3 mm), exposure — drag the canvas to tilt the camera live

## Requirements

- A WebGPU-capable browser: **Chrome/Edge 113+** or **Safari 18+**
- A dedicated GPU is strongly recommended. This was scoped to Tier 1 of a 3-tier physics spec specifically to run on modest hardware (target: NVIDIA RTX 3050 Laptop, 4GB), with an uncapped render loop that drops the internal resolution to as low as 50 % while animating to stay responsive (full resolution when paused) — full GR ray tracing is inherently expensive per pixel, so performance on integrated graphics may still be limited.

## Quickstart

```bash
npm install
npm run dev       # http://localhost:5173
npm test          # run the physics unit test suite (Vitest)
npm run build     # production build
```

`npm run verify:gpu` (dev server running) drives headless Chrome through the routes below. Any console
warning or error fails the route that logged it (the favicon 404 excepted): WebGPU never throws on a
broken shader, Chrome logs the WGSL compile error as a warning and the invalid module cascades into
zeroed buffers, so this is what turns a broken shader into a failure naming the offending WGSL line
(in seconds: the first diagnostic ends the route's wait). `probe-axis` and `probe-scale` do the same.

Validation routes (append to the dev URL):
- `?parity` — CPU↔GPU parity check for the core physics math, including the shadow-edge classifier, the camera mapping, the constraint-monitored integrator step and its step controller, the MRI disk turbulence (8 cases incl. late and negative emission times and both spin extremes, gated relative to f32 time resolution) and the synchrotron jet (plasma frequency shift, density shape, emission/absorption coefficients and slab transfer on six photon states walked into the jet), all compiled from the same shared WGSL fragments the renderer uses (61 cases; `emission-shared.wgsl` since 2026-10-02, when the turbulence and jet cases stopped testing hand-kept copies — a deliberate change to a jet constant in the shared file now fails the route at 2.0e-3). `tests/shader-twins.test.ts` fails if any WGSL function is defined in two files
- `?shadow` — **critical-curve gate**: the renderer traces every pixel with the disk and jet removed (a new `audit` compute pass), so each ray ends captured or escaped, and the image must match the exact classification `classify(ξ, η, a)` of the same rays (their conserved constants from the camera mapping) for a = 0 at 10°, a = 0.9 at 72° and a = 0.998 at 85°: no disagreement more than one pixel from the analytic critical curve, no ray out of steps there (the audit flags those, since the renderer would otherwise fall back on that same classifier), and traced shadow area within 0.1 % of the analytic one. Measured: 0 mismatches anywhere (on the curve too) and area ratio 1.0000 in all three; the gate catches a spin error of 0.05 (88 off-curve mismatches) and, via the area, 0.01 (0.26 %), and a starved step budget (every ray flagged). Plus the older structural check of a disk-lit Schwarzschild image (its dark span is the lensed inner edge of the emitter, ratio 0.758 to the critical curve; see Status)
- `node scripts/probe-axis.mjs` — visual check of the polar-axis fix: drives the sliders to a = 0, sky and jet off, at i = 72° and 8°, and asserts the band beside the pole column (x ∈ [488, 512] minus the two axis columns, |α| ≈ 0.05–0.5 M) has no more void-class pixels than a band beside it AND that the band's mean brightness is at least 0.95 of the side band's (the far-field streak was a ~50 % dimming, invisible to a dark-pixel count: measured 0.203 on main, 0.875 on the pre-cap branch build, 0.993 with the cap); fails on main and on the pre-cap build; also prints the axis columns' own dark fraction; writes `axis-i72.png` / `axis-i8.png`; runs at `?scale=1` so it always measures a full-resolution frame
- `node scripts/probe-scale.mjs` — adaptive render scale: pinned `?scale=0.5` survives a resize and a tiny odd viewport lit and warning-free, and pausing an unpinned, scaled-down view restores 100 %
- `?scale=0.5` … `1` pins the internal render scale and disables the adaptive controller (and the geodesic cache)
- `?nocache` — live tracing only (the pre-cache behaviour), for comparison
- `?golden` — bit-exact hashes of the live trace on four fixed scenes, last recorded for the 2026-10-01 step controller (`RECORD_GOLDEN=1 npm run verify:gpu` records them; per adapter, so another GPU reports SKIP)
- `?cachecheck` — the geodesic cache's exactness gate: for every jitter set and two times, a frame shaded from the cache must equal a live-traced frame with the same sub-pixel offset (see Status)

## Architecture

The physics core (`src/physics/`) is pure TypeScript with zero DOM/GPU dependencies, unit-tested in isolation against known analytic results (Schwarzschild horizon = 2M, ISCO = 6M/M/9M for a=0/extremal-prograde/extremal-retrograde, etc.). Its outputs are baked into 1D lookup tables (temperature and color) uploaded as GPU textures. A WebGPU compute shader (`src/render/raytrace.wgsl`) mirrors the core's math, tracing one geodesic per pixel and accumulating HDR radiance; a present pass resolves the accumulation buffer with exposure, ACES tonemapping, and gamma correction.

Full physics specification and derivations: `docs/specs/2026-05-30-relativistic-blackhole-accretion-design.md`

While animating, the render-scale controller *targets* 60 fps: it steps the internal resolution down (×0.9) while the GPU work time per frame is above 18 ms and up (×1.1) while it is below 13 ms, never below 50 %. It is fed the GPU busy time of each frame (from `onSubmittedWorkDone`, excluding time queued behind earlier frames), not the rAF delta, which is vsync-quantised and would let the scale only ratchet down. What that buys depends on the GPU. Measured on the dev RTX 3050 Laptop after exact derivatives: full resolution costs ≈ 72 ms at 1280×720 and ≈ 165–186 ms at 1920×1080 (a warm GPU reads higher, see the last row), so at the 50 % floor ≈ 18 ms (~55 fps) and ≈ 41–46 ms (~22–24 fps) respectively; a 1920×1080 window does not reach 60 fps on that laptop. Faster GPUs (e.g. an RTX 5050) should do proportionally better. The **FPS** and **Render scale** readouts in the panel show what a given machine actually achieves.
The numbers drift run to run with GPU temperature: the adaptive-scale row is a back-to-back pair in one session, HEAD before that change (`5c7e23b`) then the change.
Exact metric derivatives, back-to-back against its parent `b4e3f08` in one session (two runs each, 1280×720 / 1920×1080): `b4e3f08` 110.6 / 277.9 then 117.3 / 315.0; this change 71.8 / 164.5 then 72.6 / 185.5, i.e. ≈ −35…−38 % at 1280×720 and ≈ −41 % at 1920×1080. Each RK4 stage now evaluates the inverse metric once (with its exact r- and θ-derivatives) instead of five times.

Geodesic cache (2026-10-01): while playing with a still camera, frames are shaded from cached geodesics instead of re-traced, at full resolution (the scale controller only runs while tracing live). Building the cache costs 1.7–2.1 s per jitter set at 1280×720 and 4.4–5.3 s at 1920×1080 in the benchmark, which waits for every slice; in the app it rides along one slice per frame, so the first set is ready about a second after the camera stops and all four within ~3.5 s (720p) / ~5.5 s (1080p). In the app in headless Chrome on the RTX 3050 the FPS readout showed 144 (the browser's frame cap) at 1920×1080 and 1280×720 against 16 and ~34 fps for `?nocache` at its 50 % floor. The live-trace numbers in that row are higher than earlier rows because the laptop was hot after an hour of GPU tests: alternating HEAD and the pre-cache commit `604f0dc` four times showed no consistent difference in the live path (84.9–121.9 vs 93.4–117.7 ms at 1280×720).

**Step controller (perf/far-monitor, 2026-10-01):** the integrator's stride rules were re-chosen against a converged reference with one goal, fewer steps with no ray less accurate than before, and the measurement found the opposite of what the 2026-09-23 sweep suspected. Its longer far strides kept failing because of *near-field* error: rays that pass close to the polar axis inside r = 1.5·rOut, where only the H_TOL monitor bounded the stride, were up to 0.3 M off (the faint axis line, the speckled streak in the face-on jet, and the near-critical sky rays of the default view). Three changes, all in both twins (`integrator-shared.wgsl`, `trace.ts`) and gated by `?parity`: (1) **the angular caps now bound both branches of `stepSize`** (`angularCap`: at most `F_AXIS` = 0.1 of the affine distance to the axis at the current polar rate, and, new, at most `F_PHI` = 0.1 rad of azimuth per step, which resolves the ~π azimuth swing of a p_φ ≠ 0 ray turning beside the axis where p_θ ≈ 0 leaves the polar cap inactive); (2) **the far stride is `K_FAR` = 0.08, `DL_FAR_MAX` = 50** (was 0.04 / 6); (3) **the far field is monitored** at `H_TOL_FAR` = 1e-5 (was 1e30; exact forces put the GPU's |ΔH|/scale at ~1e-8 there) as a safety net: with the caps it never fires on a sweep ray. `tests/sweep-farmonitor.test.ts` (`SWEEP=1`; `HOLDOUT=1` for five views the choice never saw) scores disk hits in M and sky rays as an **on-screen displacement** through the local lensing Jacobian (an angle threshold is meaningless near the critical curve, where the sky map stretches by orders of magnitude). Over 2338 sweep rays: disk rays off by > 0.02 M 77 → 0, sky rays off by > 0.5 px 3 → 0 (worst 1.0 → 0.15 px), no fate flips, no ray worse than before, mean steps + retries 348 → 220 (**−37 %**); held-out 3265 rays: 4 → 0, worst sky 0.19 → 0.002 px, 353 → 217. The pole-passage test in `tests/trace.test.ts` (α = 0.05, θ_min ≈ 1.2e-3) now conserves the Carter constant to 2.8e-6 (was 3.5e-3) and lands 2.1e-4 M from α = 0 (was 0.0095 M); its bounds were tightened to lock that in. **Jet quadrature** is now independent of the stride: `jetStep` samples the emission at most `JET_DL` = 0.25 apart along each step's chord (a far stride entering the jet's top from r > 60 lost that segment's emission), skipping chords that never come within the jet's bounding sphere, and the geodesic cache bookmarks by the same sample points (`jetTouches`), so cached playback still equals the live trace (`?cachecheck` ≤ 3.6e-7). Measured on the GPU against a fine-step render (steps 4–8× finer, 60000-step budget) of the four `?golden` scenes at 320×180: pixels > 5 % off 12 → 7 (default), 17 → 5 (jet off), 14 → 8 (edge-on), 116 → 3 (face-on jet); mean relative error lower in all four (face-on jet 1.2e-3 → 3.7e-4, whose mean brightness now matches the reference); pixels on the wrong side of a fate boundary 43 → 18. Edge-on at a = 0.99 went 6 → 8 on that last count: those pixels are rays grazing the disk edge, and both controllers agree with the reference on every one of them in f64 (25 sub-samples each), so it is f32 noise, not the controller. `?shadow` moved 3.95 → 4.01 M: the column it scans sits half a pixel off the axis, where the old controller stopped 0.106 M short of the converged edge (4.040 vs 4.146 M in f64) and the new one matches it to 1e-4 M. Live-trace speed, interleaved A/B against `main` on the RTX 3050 (the laptop drifts thermally, so compare within a round): −20 to −39 % at 1280×720 and −21 to −31 % at 1920×1080 (table above), less than the −37 % step count because the angular caps and the finer jet sampling add work per step; cache builds −21 to −33 %. One cost: a cached frame with the jet on is ~1 ms slower (1280×720 4.1–5.8 → 5.7–6.9 ms, 1920×1080 6.5–7.1 → 7.5–8.0 ms) because the jet replay samples every 0.25 and runs ~14 % more steps; jet off is unchanged.

## Status

Tier 1 (single-GPU, real-time image) complete and verified.

**Tier 2A — Living Disk (shipped):** the accretion disk now evolves in real time. Differential rotation carries a co-rotating turbulence pattern (procedural value-noise over log-radius and pattern phase), orbiting Gaussian hot-spots are Doppler-beamed by the existing g-factor (brightening on the approaching side, dimming on the receding side), and a temporal EMA replaces the static progressive average so motion is smooth while a paused scene still re-converges to a clean still. Motion / Disk flicker / Flares sliders (the turbulence became MRI turbulence on 2026-10-03, below) and a Play/Pause control drive it live. With all features off the render is bit-for-bit identical to Tier 1 (`?parity` and `?shadow` unchanged).

**Tier 2B — Relativistic Jet (shipped; superseded 2026-10-02 by the synchrotron jet below, kept as history):** a beamed, limb-brightened, animated bipolar jet. This is **phenomenological, not an MHD or emission calculation**: the funnel is an assumed parabolic surface (ρ = 0.6 + 0.7·√|z|), brightness is a Gaussian profile peaked near the wall, and the knots are advected value noise. There is no electromagnetic field, no Blandford–Znajek power extraction, and no synchrotron emissivity computed from a field and electron distribution — the shape is chosen to *resemble* published BZ-funnel images. The one piece with real physics content is the beaming: radiance is boosted by the Doppler factor to the power 3 + α (α = 0.5), the beaming exponent for a *discrete moving blob* radiating a p = 2 power-law synchrotron spectrum. Note a steady continuous jet would take 2 + α; the code applies 3.5 uniformly to a steady funnel with knots superposed, so this is the blob exponent used somewhat beyond its remit. The tint is a fixed RGB constant, not a computed spectrum. The jet is integrated along rays before disk accumulation, optically thin with additive composite. Jet / Jet speed Γ / Jet knots sliders control the strength, relativistic beaming γ-factor, and knot amplitude live (the Jet knots slider was replaced 2026-10-03 by Flux variability, below). With the jet off, the render is bit-for-bit identical to Tier 2A (`?parity` and `?shadow` unchanged).

**Visual polish (superseded 2026-10-02: no gain or ceiling remains):** the default jet brightness/ceiling were retuned so the relativistically beamed jet reads with internal structure at low (pole-on) inclination instead of clipping to a solid white funnel.

**Polar axis (fix/polar-axis):** the Boyer–Lindquist polar axis (where g^φφ ∝ 1/sin²θ diverges) is handled physically rather than capped. `POLE_S2` is now a 1e-12 NaN guard in both twins. It was a 1e-3 floor, which did not make near-axis rays "terminate as captured" as this section used to claim: inside the 1.8° cone the floor removed the centrifugal barrier, θ ran through 0 to large negative values, the equatorial-crossing test never fired (the plane sits at θ = −π/2 on that branch), and the ray tunnelled through the axis, escaped, and rendered as background — the black wedge from each pole. The integrator now halves its step whenever the per-step drift of the null constraint H = ½ g^μν p_μ p_ν exceeds `H_TOL` = 1e-3 *relative to the magnitude of the cancelled terms* Σ|terms| (near the capture margin g^tt ~ 1e2, so an absolute tolerance would sit at f32 noise), up to `MAX_RETRY` = 8 halvings. Both constants come from a measured sweep (`tests/sweep-htol.test.ts`, run with `SWEEP=1`): 1e-3, 1e-4 and 1e-5 all pass the near-axis accuracy criterion (disk-hit radius within 0.02 M of a converged reference; the survivors measured 0.0097 M), 1e-2 fails it at 0.34 M, 1e-6 is below the f32 floor; the retry cap was never approached in f64, so 8 is headroom, not a tuned value. Mean steps per ray over the sweep's 2048 sampled rays: 338.4 with the monitor alone, 338.7 with the far-field angular cap below (retries 10 → 61 → 53). Two rulings made during implementation differ from the spec and the plan: the monitor is **off in the far field** (r > 1.5·rOut, the existing far-field step branch, `H_TOL_FAR` = 1e30) because the f32 finite-difference force at r ≈ 1000 was noise (ulp 6e-5 against an FD half-step of 1e-4), so monitoring there halved steps on noise at +35 % cost for no accuracy — the spec's "global" monitor is therefore near-field only (the forces are now exact, see the performance branch below: the GPU's |ΔH|/scale on the parity far-field step fell from 2.4e-3 to 2.7e-8, so that premise no longer holds; lifting the exemption is a tracked follow-up that needs its own gate); and a ray that exhausts the retries **proceeds with the smallest-step attempt** (the spec's literal wording) rather than breaking to the (ξ, η) classifier as the plan had it, because the classifier can only answer captured/escaped and painted a 1-px starfield seam over the disk hits on the α = 0 column (rays with |α| ~ 1e-3 exhaust the halvings — α = 0 and 0.01 did not under the old build, 1e-3 did; `tests/trace.test.ts` now checks α ∈ {0, 1e-4, 1e-3, 1e-2} all hit the disk within 0.02 M of α = 0). The rare ξ = 0 rays that genuinely reach the axis are continued analytically (θ → −θ, or 2π − θ at the south pole; φ → φ + π; p_θ → −p_θ), which is exact. The far-field exemption has a consequence the first cut missed: a ray aimed at screen β crosses the axis at r ≈ β / sin i, i.e. *inside* the exempt zone whenever β > 1.5·rOut·sin i (β > 8.3 M at i = 8°; the whole axis column at i = 1°), and there nothing but the step controller bounded the stride — a dl = 3.2 stride at θ ≈ 3e-3 carried θ to −9.2 and p_θ to −6e4, the ray escaped, and the pixel went dark. This is reproducible in f64 (the earlier "f32 residual" reading was wrong for this band). The far branch of `stepSize` is therefore **capped near the axis** in both twins: dl ≤ max(`DL_FAR_MIN`, `F_AXIS`·θ_d·r²/|p_θ|) with θ_d the angular distance to the nearer pole (F_AXIS of the affine distance to the axis at the current angular rate), `F_AXIS` = 0.1, `DL_FAR_MIN` = 0.05, chosen by `tests/sweep-axiscap.test.ts` (`SWEEP=1`) against a converged reference on the band β ∈ [9, 14] × α ∈ [0, 0.8] M at i = 8° (121 rays) and the axis column at i = 1° (65 rays): the rule was zero fate flips on both sets, then the fewest rays off by more than 0.02 M, within +15 % mean steps on the band; only F_AXIS = 0.1 has zero flips (the uncapped controller had 16 and 1), it leaves 45 + 5 rays with a sub-pixel radius error > 0.02 M, and costs +12 % steps on that band (+4.5 % on the axis column, +0.1 % over the sweep's 2048 rays). The angular cap, not the monitor, is what buys accuracy there: with the monitor on everywhere and no cap the band still has 95 wrong rays, because the *relative* drift measure cannot reject a step whose garbage momenta inflate its own scale. A step that moves θ by more than 0.5 rad is no longer accepted as a disk crossing (a legitimate near-field step moves it by ≤ ~0.07 rad; `reflectAxis` assumes a single crossing). What `?parity` gates on the shipped shader bytes: `stepGeodesic` (monitor, halving, retry count, ok flag), `stepSize` (the shader computes its own stride on a sentinel and reports it — near branch, far branch and the angular cap), `reflectAxis`, and the constants `H_TOL`/`MAX_RETRY` (eight integrator cases: far field, far field near the axis on the streak ray, strong-field equatorial, near horizon, near axis, a forced retry the harness refuses to let be vacuous, a barrier step, an axis reflection). What it does *not* gate: the render loop around those calls — its far-field select(), the disk test and its |Δθ| guard, the capture/escape tests — which only `?shadow` and the probe exercise. The catch threshold, concretely: a one-step state desync of ≳ 2e-3 absolute in the momenta or ~6e-3 in r on the near-field cases; a retry, ok or constant mismatch scores ≥ 1. This changes pixels near the axis and, because the near field is monitored everywhere, marginally elsewhere; headless fps went 0.54 → 0.78 with the far-field exemption. `scripts/probe-axis.mjs` is the visual gate: it counts void-class pixels (RGB sum < 80) over the band beside the axis column above the shadow (x ∈ [488, 512] minus the two ξ ≈ 0 columns, which have no barrier and are clean on every build) against a side band; it fails on the old shader at both inclinations and passes here. Note what that count can and cannot see: the pre-cap streak was a ~50 % *dimming* (half the jittered samples escaped), not void-class pixels, so the dark-fraction criterion alone passed on the pre-cap build too (0.162 vs 0.157); the probe's second assertion, band/side mean brightness ≥ 0.95, is what catches it (0.874 on the pre-cap build 4a98a7f → FAIL at i = 8°; 0.993 with the cap; 0.203 on main). 0.95 sits between the two measured branch states with margin on both sides — a discrimination threshold between known states, not a tuned one.

Known limitations of the fix, stated plainly: (a) *Near-axis residuals at low inclination.* An earlier revision of this paragraph attributed a dark, speckled streak beside the axis column above the shadow at i = 8° to f32 barrier-step precision. That was wrong: the streak was the unmonitored far-field axis crossing described above (β > 1.5·rOut·sin i), reproducible in f64, and the angular cap removes it — the band beside the axis now reads 98–103 % of its neighbours' brightness over rows 0–214 (was 44–62 % on columns 496–503 over rows 0–130), leaving a faint 1–2 px line on the axis column itself, ~2–3 % *brighter* than its neighbours with sparse dark speckles. What remains is (i) sub-pixel: 45 of the 121 band rays land more than 0.02 M (half a pixel) from the converged disk-hit radius with the shipped cap (a tighter cap trades that for steps: 35 at +27 %), and (ii) lit pixels on columns 499–500 *inside* the shadow. Under finite-difference forces there were about six (rows 219–313 of the i = 8° probe image, RGB sums 108–193, three of them deep inside at rows 230, 297, 313), where the f64 twin captures every ray. With exact forces in both twins (performance branch) the deep ones are gone: what remains is a 2–4 px taper of the axis line into the top rim of the shadow (rows 216–219 across probe runs, directly below `shadowTop` = 215; the final-HEAD run lit rows 216–218 with RGB sum ≥ 80), and the `?shadow` centre column, which is this same ξ = 0 column, no longer stops early on a lit pixel (its radius moved 3.89 → 3.95 M, the axis column's top edge now matches its neighbours'). The 2 % p_θ divergence the parity "barrier" case used to document as f32 was *also* misattributed: it was the CPU's finite-difference half-step h = 1e-5 against the shader's 1e-4; both twins now use exact derivatives and the barrier state agrees to 6.8e-5 relative. At i = 72° neither residual is measurable (column means flat to ±1 %). (b) The far-field monitor exemption was motivated by f32 finite-difference noise that no longer exists (see above); it stays until a follow-up with its own gate lifts it, and the far parity case still compares positions only (its momenta now agree to 3e-8). (c) *Resolved 2026-10-01:* the thin bright line that used to show on the α = 0 column with the jet on is gone since the angular step caps bound the near field (measured: the jet's own light across the α = 0 column is smooth to < 0.2 % at i = 72° and 8°). The faint vertical line that remained above the shadow was not the jet: it was the turbulence seam described under *Disk turbulence seam* below.

**Lensed sky background (shipped):** the procedural starfield is replaced by a real Milky-Way panorama (ESO/S. Brunier, CC BY 4.0) sampled along each escaped ray's gravitationally-bent direction, so the background warps around the shadow into a lensed ring (most pronounced near edge-on inclination). **Photon-ring detail (shipped):** rays that exhausted the integrator's step budget previously fell
out of the loop still holding their initial black colour, so step-starved rays rendered as shadow —
an artifact that swallowed the n=1 photon subring (at a=0.9 one winding near the prograde photon
orbit r≈1.56M costs ~3900 steps against a budget of 1200). Exhausted rays are now classified by
their conserved impact parameters (ξ, η) against the analytic Kerr critical curve, and a "Detail"
slider exposes the step budget (default 4800). This does not fully resolve the ring: per-winding
step cost varies roughly 8x across the photon shell (at a=0.9, ~3900 steps at the prograde edge
r≈1.56M vs. ~500 at the retrograde edge r≈3.91M), so a budget of 4800 resolves the retrograde side
completely but leaves the innermost prograde part of the n=1 subring still budget-limited. n=2
subrings are not visible and cannot be at the default field of view — successive subrings are
thinner by a factor of roughly e^(−2π) ≈ 1/535, well under one pixel at the default `fovScale`;
seeing one would require a narrow-FOV zoom, which is out of scope — and a zoom alone would not
suffice, since n=2 is also bounded by integrator accuracy: the geodesic forces are now exact
derivatives of the inverse metric (`metricUpperGrad` / `gUpGrad`, no finite differences), but the
step is still f32 non-symplectic RK4 with a per-step constraint tolerance of 1e-3, and a near-critical
spherical orbit amplifies any per-step error by the same e^(2π) ≈ 535 per winding, so it reaches O(1)
after a few windings. Note this is the first feature
that does **not** preserve the project's bit-identical-when-off property: correcting the artifact
necessarily changes pixels near the shadow edge. `?parity` was math-only at the time and was
unchanged by this feature (it has since grown the shadow-classifier, camera and integrator
blocks described under the polar-axis fix).

**Geodesic cache (perf/geodesic-cache, shipped):** a ray's path depends only on spin, inclination, field of view, `rObs`, the disk radii, the step budget, the jet length and the resolution; time enters only afterwards, in the disk's co-rotating pattern and the jet's time-dependent emission (flux-driven knots and filaments since 2026-10-03; light-travel delay since 2026-10-01 — both shading-only). So while playing with an unchanged camera each pixel's geodesic is traced once per jitter set (4 fixed rotated-grid sub-pixel offsets) and recorded — disk hit (r, φ, g), escape direction, or shadow — together with a *bookmark* (the integrator state where the ray first enters the jet's geometric envelope, and the number of steps to its last step inside it). Each frame then re-colours the disk and sky from the record and re-integrates only the bookmarked jet stretch with the real integrator: 6–14 % of pixels carried a bookmark and the replay was 0.7–3.2 % of a full trace's steps (`tests/sweep-jetenvelope.test.ts`); after the jet envelope widened to q ≤ 1.51 for the flux-driven jet width (2026-10-03) it is 8.2 / 13.5 / 18.2 % bookmarked and 2.0 / 2.2 / 8.3 % replayed (default / edge-on / face-on), and the bookmark buffer was resized to 28 % of pixels (1.5 × the face-on maximum; was 21 %). Paused stills, dragging and any ray-path slider use the live trace exactly as before; shading-only sliders (exposure, flares, turbulence, jet strength/speed, flux variability, sky) never rebuild. The cache uses W·H·16 bytes per jitter set plus the bookmark buffer; it drops to 2 or 1 sets, or stays live, when the GPU's binding limit or a 512 MB budget would be exceeded, and a full bookmark buffer turns its overflow pixels back into live-traced ones. Exactness, measured by `?cachecheck` on six scenes: every cached frame equals the live trace to ≤ 4.2e-7 relative per pixel (jet pixels included; bookmark overflow forced on 66,992 pixels: ≤ 3.5e-7); the recorded geometry is bit-identical to the live pass's. One ruling: the *procedural* starfield (sky slider at 0) is not reproducible to that level across separately compiled GPU entry points — its hash takes `fract()` of values in the hundreds and multiplies star brightness by ~90, so last-bit compiler differences reach 2.7e-3 on dim star pixels — and `?cachecheck` reports those pixels instead of gating them; with the panorama at full strength (the default) the starfield is now skipped entirely, which made sky pixels bit-identical. The live trace stays bit-identical to the pre-cache shader (`?golden`).

**Real-object presets (feat/real-object-presets, 2026-10-01):** the disk now has a physical peak temperature and is shaded by what a camera would record. *Temperature:* `pageThorneFluxShape` is the Page–Thorne flux for Ṁ = M = 1, so one face radiates F = Ṁ c² · shape(r) / (4π r_g²) and T_peak = (F_max / σ)^{1/4}, with Ṁ = λ L_Edd / (η(a) c²) (`src/physics/units.ts`; λ is the Accretion slider, the fraction of the Eddington luminosity; η = 1 − E_ISCO). Check: 10 M_☉, a = 0, λ = 1 → 7.0 × 10⁶ K. *Brightness:* a blackbody seen with frequency shift g is a blackbody at g T (I_ν/ν³ is invariant), so a disk pixel is the **visible-band radiance** of a blackbody at T_obs = g · T_peak · shape(r), divided by the visible luminance at T_peak (uniform `lumNorm`, so exposure means the same for every object). This replaces the bolometric (g·T/T_peak)⁴ law in every view: the cooler outer disk is now far brighter relative to the inner edge (the default exposure moved +1.6 → −1.0 EV to keep the same overall level, and the turbulence now shows across the whole disk), and a cool disk glows only near its peak. **Synchrotron jet (feat/synchrotron-jet, 2026-10-02):** the hand-made jet (Gaussian wall, fixed blue tint, δ^3.5 blob beaming, `JET_GAIN`/`JET_CEIL`, per-preset strength) is replaced by synchrotron emission and absorption from a magnetic field and a power-law electron population, transferred along the existing Kerr geodesics (spec `docs/specs/2026-10-02-synchrotron-jet-design.md`). *Field:* a magnetically arrested disk's horizon flux Φ = 50 √(Ṁc) r_g (Gaussian; Tchekhovskoy, Narayan & McKinney 2011), carried up the existing parabolic funnel by flux conservation (B_p = Φ/πρ_f²) plus the wound-up force-free toroidal field B_φ = B_p ρΩ_F/c with Ω_F = Ω_H/2. Its Blandford–Znajek power (κ = 0.05) is 0.977 Ṁc² at a = 0.9 and **4.26 × 10⁴³ erg/s for M87\***, inside the published 10⁴³–10⁴⁴. *Flow:* outward along the funnel's streamlines in the zero-angular-momentum frame with M87's measured linear acceleration Γ ∝ R ∝ z^0.58 (Mertens et al. 2016), applied to the proper speed as in force-free linear acceleration: Γβ = √(Γ₂₈₀² − 1) (|z|/280 r_g)^0.58, so Γ = Γ₂₈₀ at 280 r_g, Γ ∝ z^0.58 where Γ ≫ 1, and β ≈ 0.25 at 10 r_g and 0.58 at 60 r_g at the default; the **Jet speed** slider sets Γ₂₈₀ (1.5–8, default 2). (The first version clamped Γ = max(1, Γ₂₈₀ (|z|/280)^0.58), which held the plasma at rest below ~85 r_g, the whole view: frozen knots and no beaming. The final review caught it.) *Electrons:* N(γ) = K γ^−2.4 above γ_min = 10 (optical index 0.7, inside M87's measured 0.6–0.9); K ∝ B² × the old wall/falloff/knot/turbulence shape. *Coefficients:* pitch-angle-averaged Rybicki & Lightman 6.36 and 6.53, with the low-frequency forms below ν_min = 3γ_min²qB/4πm_ec matched at ν_min; they agree with a direct numerical integration of the single-electron spectrum to 0.05 % (j) and 0.07 % (α) (`tests/synchrotron.test.ts`). A correction found while planning: 6.53's constant is per unit *energy* (C_E = K (m_ec²)^(p−1)); the first estimate used it per unit γ and was off by 3 × 10⁸. *Brightness:* with uncooled electrons, an equipartition or magnetisation-set density makes the jet radiate more than its total power (optical-emitting electrons cool in ~0.1 s against minutes of flow time), so the absolute density is set by **energy conservation** instead: the CPU chooses K's scale so the jet's optically thin visible (400–750 nm) luminosity in the rendered region (both lobes) equals **ε × P_BZ**, with the **Jet efficiency ε** slider (log 10⁻⁵–10⁻¹, default 2 × 10⁻³ from M87's optical nucleus, ~10⁴¹ erg/s, against its jet power). *Transfer:* the exact frequency shift D = p·u from the photon momentum the integrator carries and the plasma four-velocity; per jet sample (every 0.25 M along the ray) a uniform slab of plasma-frame path r_g D dλ: I += j ds (1 − e^−Δτ)/Δτ · e^−τ, τ += α ds, at 450, 550 and 650 nm; disk and sky behind the jet are attenuated by e^−τ (cached frames too: `?cachecheck` still 0.00e+0). *Colour:* the three bands, each constant over 360–500 / 500–600 / 600–830 nm, go through the same CIE sum as the disk via a constant 3×3 matrix into the disk's units, times the disk's `lumNorm`, so jet and disk brightness are directly comparable (a blackbody fed through the jet path reproduces the disk path's luminance to 0.6 %). The panel has a **Jet** checkbox; presets switch the jet on (M87\*, Cygnus X-1, GRS 1915+105) or off (Sgr A\*, Gargantua). At spin 0 there is no BZ power and so no jet.

*What the model predicts* (jet light / disk light in view, 640×360, sky off, 5 times, default ε and Γ₂₈₀; reported, not tuned): **Default view 3.2 %, M87\* 22 %**, the approaching lobe now Doppler-boosted over the counter-jet. (Not comparable with the EHT's 230 GHz jet-base bound the old hand calibration used: that is radio against a hot flow, this is visible light against a thin disk the caption says is not M87\*'s real flow.) (Superseded by the cooled jet below; kept as the record of why it was needed.) **The X-ray binaries are outside the model's energy-consistent range.** Cygnus X-1 and GRS 1915+105 draw 1.2 × 10³× and 3.1 × 10²× the disk's light, but their field (B₀ ~ 4 × 10⁸ and 2 × 10⁹ G) puts ν_min at ~3 × 10¹⁶–2 × 10¹⁷ Hz, so the visible band sits two to three decades down the electrons' low-frequency tail. The density that makes that tail carry ε × P_BZ in the visible makes the same electrons radiate 0.6× (Cygnus X-1) and 6× (GRS 1915+105) P_BZ at and below ν_min alone (more again for any power law extending above γ_min), and the optically thin jet at ν_min would let it escape: energetically impossible. The visible jet is then optically thick (τ₅₅₀ ~ 10²–10⁴) at the γ_min = 10 source-function limit (~2.5 × 10¹⁰ K), which hardly depends on the density, so it renders saturated white at the default exposure; their preset captions call it an overestimate outside the model's range. Making these consistent needs an energy budget over the whole synchrotron spectrum, which needs a γ_max or a cooling break: a model choice left for a follow-up. (Their inner disks' visible light is only the Rayleigh–Jeans tail of a 10⁷ K blackbody; their real optical light comes from the irradiated outer disk and the companion star, outside this view.) The counter-jet shows through the upper part of the shadow in the default view. **Cooled jet (feat/cooled-jet, 2026-10-02):** the synchrotron jet's energy budget now covers the whole spectrum (spec `docs/specs/2026-10-02-cooled-jet-design.md`). The visible-band budget above was energetically impossible for the X-ray binaries; the fix follows from a measurement: comparing each electron's synchrotron cooling time with the plasma's travel time, every electron in view is in **fast cooling** — the energy that survives one flow time is γ ≈ 10⁻³ in the default view, 0.03–0.5 for M87\* and 10⁻⁶–10⁻⁴ for the X-ray binaries — so the jet radiates, locally, what its electrons are given. *Injection:* the electrons are accelerated in place with a broken power law fitted to M87's measured core spectrum (synchrotron peak at 10^11.5–10^12 Hz, α ≈ 1.1 from infrared to X-rays, Prieto et al. 2016 and the broad-band nucleus modelling of arXiv 2406.17200; α ≈ 1.5 from optical to UV, Perlman et al. 2011): N ∝ γ^−2.2 for 40 ≤ γ ≤ 1200 and γ^−3.0 above, injected power ∝ B² × the funnel's shape. *Cooling:* exact synchrotron losses dγ/dt = −k u² (u = γβ, k = σ_T B²/6πm_ec) with injection running for the plasma's proper time since it left the base, t′ ∝ |z|^0.42 in closed form for the measured acceleration profile; the population is the closed-form solution N̂ = (1/u²) ∫_γ^G g, G = coth(arccoth γ − s), s = k t′ (it solves the continuity equation to 1e-8 and, fast cooling, radiates 99.999 % of what is injected). *Emission and absorption:* the exact cyclo-synchrotron spectrum of each electron — the Bessel series over harmonics, direction-integrated and averaged over pitch (Bekefi), with large orders from the uniform Airy expansion — matches the Larmor power to 0.03 % and the synchrotron formula to 1.3 % at γ = 10, where it hands over; the X-ray binaries' visible light comes from cooled electrons at γ ≈ 0.4–3, which the old closed forms could not describe. Absorption uses the exact isotropic formula (Ghisellini & Svensson 1991; the contraction passes a Kirchhoff check against thermal populations). Both are tabulated over ν′/ν_B (10⁻⁴–10¹⁰) × the cooling depth s (10⁻⁷–40): `public/synch-table.bin`, 1612 × 300, 3.9 MB, built by `node scripts/build-synch-table.mjs` on every core in 33 minutes. Absorption is integrated finite-volume (the population's derivative exactly across each momentum cell, on a grid refined where slow-cooling edges meet the harmonic structure): it is converged to ≤ 0.3 % against a 2× finer grid and within 3 % of a 10× finer one at the points the final review found up to 10× off. The table conserves energy to 0.4 % (s ≥ 10⁻³; below, uncooled electrons emit past its top edge), and lookups match a direct contraction at off-grid points within 1 % (emission) and 2 % (absorption). Edges: below s = 10⁻⁷ every electron that matters is uncooled (N ∝ s); above s = 40 the table extends linearly in s, because electrons cooled to rest keep accumulating and their absorption at the cyclotron fundamental grows with s (this assumes they are never re-heated — no Coulomb or synchrotron-boiler thermalisation — which a real jet would add, capping that absorption); above ν′/ν_B = 10¹⁰ it follows the last two columns' slope (within 7 % even where the cooling break lies just past the edge, the extreme Mass/Accretion corner). 144 cells hold genuinely negative absorption — a weak cyclotron maser at the low edge of the fundamental of electrons at the cooled population's switch-on edge (ν′/ν_B 0.16–1.5, s ≈ 0.15; converged on a 10× finer grid) — stored as zero: the model leaves that amplification out. The final review also caught a NaN in one column (a cancellation in the Bessel functions' uniform expansion right at the turning point, now a series) that had zeroed the table at ν′/ν_B ≈ 12.7; the build now refuses any non-finite value. the shader samples it as a texture with the same bilinear lookup and edge extensions as the CPU (`?parity`: |Δ ln| ≤ 1.5 × 10⁻⁵ including Cygnus X-1 states). *Energy budget:* the injected power, counted as energy at infinity (α_lapse² Γ √(g_rr g_θθ g_φφ) per coordinate volume), equals **η × P_BZ**, with P_BZ now carrying the high-spin factor f = 1 + 1.38ω² − 9.2ω⁴ (Tchekhovskoy, Narayan & McKinney 2010; M87\* 4.46 × 10⁴³ erg/s). The **Jet efficiency η** slider (log 10⁻⁴–1) defaults to **η = 0.0553**, the value at which the M87\* preset's thin νL_ν(550 nm) equals its optical nucleus, 10⁴¹ erg/s — 5.5 % of the jet power given to radiating electrons, inside the 1–10 % range dissipation models give; the HST nucleus aperture holds more jet than the ±60 r_g view, so it is an upper bound. *What it predicts* (jet ÷ disk light in view, 640×360, sky off, 5 times; reported, not tuned): Default view 6.2 %, M87\* 30 %, Cygnus X-1 2.1 × 10²×, GRS 1915+105 39× (the visible-band budget gave 3.2 %, 22 %, 1.2 × 10³×, 3.1 × 10²×). The X-ray-binary jets are 6–8× fainter than before and now conserve energy; they still outshine the inner disk, which emits only the Rayleigh–Jeans tail of a 10⁷ K blackbody, because their cooled electrons radiate near the cyclotron frequency at brightness temperatures ~5 × 10⁹ K, so they saturate the default exposure. Measured speed is unchanged within thermal noise (RTX 3050, interleaved against the previous build: cached jet-on frames 4.5–5.1 → 5.1–5.3 ms at 1280×720, 7.0 → 6.9–8.4 ms at 1920×1080). `?golden` re-recorded (default 863d37e1, jet-off 390e436d, edge-on 511467c1, face-on-jet ebc01002, delay 048d42ef); jet-off moved by last-bit rescheduling at each jet-code change (each time the jet-free kernels of the old and new builds were bit-identical). The final-review fixes left the measured jet ÷ disk light unchanged to four digits: they correct absorption detail, not the jets' total light. A new `?cachecheck` scene puts Cygnus X-1's optically thick jet over its disk: cached equals live, max 0.00e+0 over 85,490 jet pixels.

**MRI disk turbulence (feat/mri-turbulence, 2026-10-03):** the disk's decorative value noise is replaced by turbulence with the measured properties of magnetorotational (MRI) turbulence in thin disks (spec `docs/specs/2026-10-03-mri-turbulence-design.md`). *Why:* the old noise was a pattern frozen into the flow forever, so differential rotation wound it into ever-tighter stripes as the animation ran; real MRI structures live a fraction of an orbit. *Field* (`turbulenceAt` in `src/physics/emission.ts`, sole WGSL twin `turbulenceFieldE` in `emission-shared.wgsl`): hashed standard normals on a lattice in (ln r, φ), smoothstep-interpolated and renormalised by √Σw² so every point is exactly N(0, 1), two octaves, 2π-periodic in φ. Each lattice row runs a clock with period T_c = 0.32 T_orb(r) (Kerr Keplerian); a *generation* is born every tick with its own lattice values, is frozen into the Keplerian flow from birth (sampled at φ − Ω(r)·age), and is cross-faded out over the next tick (cos/sin weights, unit variance). Shear acting on each generation for its age makes trailing spirals; nothing lives longer than 2 T_c, so the winding never runs away. *Emission:* MRI turbulence changes the local dissipation, so it modulates the emitted flux: F = F_NT × exp(σg − σ²/2), lognormal (Hogg & Reynolds 2016) with mean exactly 1, so the turbulence redistributes the disk's light without changing its bolometric average. An optically thick disk radiates that flux as a blackbody at T × F^(1/4), so the renderer shades each pixel at the modulated temperature through the existing colour table (final review: the first version applied the factor as a grey multiplier on visible radiance, which misstates the visible contrast). The visible contrast therefore depends on the disk's temperature, as it would in reality: at σ for 2 % bolometric, about 1.2 % in the visible for the default 3 × 10⁴ K disk, 0.6 % for a 10⁷ K X-ray-binary disk (Rayleigh–Jeans tail) and 3.4 % for a 6,000 K disk (measured in the final review). *Targets* (Schnittman, Krolik & Hawley 2006, SKH06) and the values measured on the CPU twin (`tests/turbulence.test.ts`): structure sizes, i.e. where the variance spectra peak after removing the shear, λ_φ = 25° (measured 25–26°) and λ_η = 0.26 in ln r, δr/r = 0.3 (measured 0.25–0.26), from lattice cells of 0.086 in ln r and 49 around the ring; the correlation following the flow falls to 1/e at 0.3 T_orb (measured 0.30); the spiral is not an input: shear over one lifetime gives dφ/d ln r = −0.9π in SKH06, −0.95π here, and −0.94π after ~1000 orbits (no runaway); mean 0.010, variance 0.997, kurtosis 3.03. *Amplitude, within observed bounds:* the default 2 % rms sits inside what thermal-state disks are observed to allow: the thermal state is defined by a whole-source rms below 7.5 % (0.1–10 Hz, 2–20 keV; McClintock & Remillard 2006, Remillard & McClintock 2006 Table 2), and in the soft state the disk component itself is near-constant, the variability coming from the high-energy tail (Churazov, Gilfanov & Revnivtsev 2001). **Jet knots from horizon-flux variability (feat/jet-flux-knots, 2026-10-03):** the jet's knots (1-D value noise sliding outward) and its cross-funnel "churn" (a noise pattern frozen in space) are replaced by the imprint of the horizon magnetic-flux history of a magnetically arrested disk, launched at the jet base and carried outward by the plasma, plus filaments frozen into the moving plasma (spec `docs/specs/2026-10-03-jet-flux-knots-design.md`, with its "Corrections from planning"). *Physics:* in MAD simulations the horizon flux φ_BH erupts quasi-periodically, every 1000–2500 M (~1500 M; arXiv 2510.25842), each eruption a quasi-exponential drop with the converged plasmoid-reconnection e-folding of 500 M lasting a few hundred M (Ripperda et al. 2022), followed by a slow rebuild as gas re-advects flux; its rms swing is σ/μ = 0.209 at a = 0.9 (Narayan et al. 2022; other runs give 0.11). The jet power goes as φ_BH², and a drop then recovery imprints a thin–thick width pattern that travels down the jet with the plasma (Tsunetoe, Narayan & Ricarte 2024). Shells collide (internal shocks proper) mostly beyond the 60 M view, so what is visible here is their driver. *Generator* (`src/physics/flux-history.ts`, WGSL twin `fluxRatioJ`): a deterministic sawtooth — eruption k at 1500 (k + 0.5 + u_k/3) M (gaps 1028–1984 M), depth δ_k = 0.5058 (1 + 0.5 v_k), exponential drop to the depth, linear refill; the mean depth is calibrated so φ's rms is 20.9 % (`scripts/calibrate-flux.ts`; moments ⟨d⟩ 0.262371, ⟨d²⟩ 0.092607, ⟨d³⟩ 0.037282 over 10⁶ M). τ(60 M) = 166 M at Γ₂₈₀ = 2). *Response:* at flux ratio f = φ/φ̄ the funnel is √f wider (flux conservation with the edge in pressure balance) and the density f times higher, so power per length goes as f² (more exactly f²(A + Cf): the toroidal field grows with radius); **Faster integrator: Carter's equations in Mino time (perf/mino-integrator, 2026-10-08):** the renderer's geodesic
solver is replaced; the metric, the geodesic equations' content and every emission model, constant and calibration are
unchanged (spec `docs/specs/2026-10-07-mino-integrator-design.md`, plan `docs/plans/2026-10-07-mino-integrator.md`). A
null geodesic in Kerr has three constants (E, L_z, Carter's Q), so per ray the camera computes ξ = L_z/E and η = Q/E² once
and the state is integrated in Mino time (dλ = dl/Σ), where the r and θ motions separate: w = 1/r with w'' = R̃'(w)/2
(R̃ = w⁴R(1/w) is O(1) everywhere; in r the conserved r'² − R was set by far-field error at R ~ 10¹² and swamped R near the
hole), θ itself with θ'' = Θ'(θ)/2 (u = cos θ cannot carry sin²θ to relative precision near a pole), φ, a regularised time
τ = t + r₀ + F(w, w') and a regularised affine length ℓ = l − r₀ + w'/w as quadratures (t' ~ 1/w² made 6e-4 M delay
errors in f32; the emitters' weights were differences of l ~ 1000). Dormand–Prince 5(4), adaptive, MINO_TOL = 1e-5, with
the drift of both first integrals (w'² − R̃, θ'² − Θ) in the error norm at MINO_CTOL = 1e-3 of it and a rounding floor;
precise sin/cos (`sinCosP`, Cephes, ~1 ulp: WGSL's built-in cos(1°) is 2e-5 off on Intel) for all Mino trig and the
camera's (ξ, η); a hemisphere frame (θ measured from the nearer pole) so near-pole rays keep relative precision in f32;
disk and escape-sphere hits by a landing DP5 step refined by safeguarded Newton (the 4th-order Hermite crossing was 1.4e-4
rad off in φ on near-critical rays); steps that would carry w past 0 are rejected (WGSL's log of a negative is finite on
Intel, and such steps had read far rays' sky off the escape sphere); sky directions read on r = 1.2 r_obs, where the
reference lands too. The jet and the hot flow are integrated with a composite midpoint rule on the step's dense output
(hot flow every 0.125 · max(1, r/8) M, half the old 0.25 left-sample spacing). Every function has a CPU twin
(`src/physics/trace-mino.ts`) gated by `?parity` one step at a time from identical f32 inputs.

*Accuracy.* Two gates, both against converged references: `tests/sweep-mino.test.ts` (`SWEEP=1`, CPU, f64; 12 ray sets
incl. near-critical, grazing, near-axis and both 1.3 mm objects; references cross-checked against Mino at 1e-11) and
`?accuracy` (GPU, the shipped renderer's own cache-build entries over six 40×40 views, against
`src/test/accuracy-ref.json` and the old renderer's entries recorded on the same adapter). On the GPU the new renderer's
largest errors are r 9e-6–1.5e-4 relative, φ ≤ 1.3e-5 rad, delay ≤ 4.9e-5, sky ≤ 0.005 px, 1.3 mm intensity ≤ 8e-4
(median 5e-5 Sgr A*, 1.8e-5 Gargantua) against the old renderer's 4.8e-5–1.2e-4, ≤ 2.7e-4, ≤ 1.4e-3, ≤ 0.036 px and
≤ 1e-2 (median 1.1e-3), with no fate flips. Per pixel, errors are judged against floors (1e-5; 0.01 px; the 1.3 mm
rule's quadrature error; each raised to the pixel's own f32 input conditioning): the old renderer exceeds its floor on
960–1265 pixels of each geometry quantity and 235–261 of the 1.3 mm views, the new one on at most 34 (delay, edge-on) and
on none at 1.3 mm. The original rule, no pixel worse than the old renderer, could not pass at any practical tolerance:
both renderers share f32 floors that a 1-ulp input nudge does not capture (near-critical rounding amplified by the photon
orbit, and a ~−1e-5 bias in the f32 log-sum of the hot flow's coefficients), and the old one beat the new only where its
own error happened to cancel (17 of ~9600 pixels; MINO_TOL 1e-6 left 9 at +12–25 % cost). By decision the gate now
fails a pixel that exceeds its floor, its old error and the old renderer's typical exceedance, and fails a view where the
new renderer exceeds floors more often or by more than the old one (`src/test/accuracy.browser.ts`).

*Jet.* The emitters sample the step's dense output. For the jet, only the part of a step inside its bounding sphere is
sampled (bisected on the dense w; exact, the shape is 0 outside), sub-interval boundaries march in affine length at
min(0.25, 0.02 (r − r₊)) M (the density the old near-field steps gave; a flat 0.25 under-sampled the jet base), and samples
clearly outside the funnel are rejected on their dense (w, θ) alone. Against a 16× finer render of the three jet scenes
(default / edge-on / face-on), pixels > 5 % off 69 / 97 / 9 and mean error 3.4e-3 / 4.8e-3 / 6.4e-4, against the old
renderer's 95 / 127 / 10 and 5.2e-3 / 5.8e-3 / 1.7e-3. (The first Mino cut, deployed briefly on 2026-10-08, spread each
step's samples over the whole step and ran the visible view with the jet on 1.6× slower than the old renderer.)

*Speed* (bench minima, two rounds interleaved with `main`, RTX 3050 Laptop): visible live 1280×720 jet on 46–47 ms vs
60–66 (jet off 20 vs 47–50), 1920×1080 113–141 vs 173–194, 1.3 mm live 101–114 vs 133–139, 1.3 mm with a hotspot

**MAD electron heating for the hot flow (feat/mad-rbeta, 2026-10-08; spec `docs/specs/2026-10-08-mad-rbeta-hotflow-design.md`):**
the hot flow's fixed electron temperature (T_e ∝ r^-0.84) is replaced by the R-β heating of the EHT's GRMHD libraries
(Mościbrodzka et al. 2016): virial ions (k T_i = m_p c²/3r), a magnetically arrested field set by the midplane density
with Broderick's normalisation at β_eq 1 (it used β 10 everywhere), so the local ion β = 2 e^(−z²/2ρ²) is 2 at the
midplane, and T_e = T_i / R(β) with R_high 160, R_low 1: cold electrons where the gas pressure dominates (R 128 at the
midplane), hot ones toward the funnel.
Density, velocity, emissivity and transfer are unchanged. Why: on the CPU twin, only *where the electrons are hot* moved
M87\*'s ring; the GRMHD-calibrated MAD velocity (arXiv 2607.21852), density slope and disk thickness left it at 35.5 µas,
a flatter temperature reached 36.3, while R-β at the EHT libraries' R_high 80–160 gave 41.9–42.2. Results (table above):
**M87\* 41.8 µas against the EHT's 42 ± 3, gated inside 2σ** and robust to a 15 µas blur; Sgr A\* 57.3 µas, reported at
+2.4σ (both objects come out at α = D/θ_g ≈ 11, as GRMHD images do; the EHT's Sgr A\* ring is α ≈ 10 for the preset's
mass and distance). Sgr A\*'s ring is flat-topped from ~51 to ~61 µas, so its peak is located to ~3 µas, not 0.5: the
CPU twin is measured on the GPU's frame (192², 28 M; on the 96², 26 M calibration grid the peak moved by up to 8 µas)
and checked to 3 µas, M87\*'s to 0.5 µas. Recalibrated: n₀ (Sgr A\* 1.43e7, M87\* 1.14e5 cm⁻³; fitted to the flux inside the 26 M calibration frame:
the hot off-plane electrons emit out to r = 50, so the model's total compact flux is ~8 % higher for Sgr A\*, 2.58 Jy in a
52 M frame by a CPU probe) and the hotspot amplitude A₀ 692 (was 9.22) for ALMA's +0.3 Jy: the midplane electrons where
hotspots orbit are now ~9× colder (2.8e9 vs 2.6e10 K at r 10) and their emissivity far lower, so the hotspot multiplies
them ~600×; a real flare heats its electrons instead (a limitation).
`?accuracy`: the 1.3 mm reference rows were rebuilt for the new emission. The pre-Mino renderer no longer exists to
re-record its mm entries, so each mm scene is held to this renderer's own statistics at the change with headroom (pixels
above floor ≤ 2 × measured + 5, worst ≤ 3 × measured, on every adapter): Sgr A\* 0 above floor, worst 0.58× (bounds 5,
1.74×), Gargantua 5, 1.28× (bounds 15, 3.84×). Intensity is judged where the reference or the renderer reaches 1e-9 of
the scene's peak (dark in both: the GPU skips gas below its ln n < −40 density cutoff by design and nothing is visible;
`src/test/accuracy-judge.ts`). Hot off-plane electrons now emit out to the flow's cutoff at r = 50, so 16 % (Sgr A\*) and
25 % (Gargantua) of the reference rays, nearly all faint, no longer converge to 1e-6; with the dark ones, intensity is
scored on 1235 (Sgr A\*) and 607 (Gargantua) of 1600 pixels. Limitations: R-β with
virial ions and a midplane-set field is a semi-analytic stand-in for GRMHD (no turbulence, flux eruptions in the field
or funnel geometry beyond the density's Gaussian); the velocity is unchanged (Pu 50/50).
